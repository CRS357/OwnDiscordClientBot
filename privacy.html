Privacy policy

How the Discord Bot Client handles information

Effective date: October 8, 2026

This policy describes the Discord Bot Client web application (“Client”), maintained by crsgamer357 (“operator,” “I,” “me”). The Client is a self-hosted interface that uses a Discord bot account and Discord’s services. It is not operated by or affiliated with Discord Inc.

Deployment matters: The operator of the running bot server controls its configuration, access, logs, and local files. This policy describes the project’s default self-hosted design; the operator must keep it accurate if a deployment adds analytics, changes storage, or uses additional services.

1. Information the Client handles

When the bot has the relevant permissions and Discord intents, the Client can receive and display information available to that bot, which may include:

  • Discord user IDs, usernames, display names, avatars, server nicknames, role colors, roles, and presence or activity details made available to the bot.
  • Server, category, channel, and role names and IDs, plus channel permission information needed to show accessible parts of a server.
  • Messages, replies, mentions, reactions, embeds, stickers, attachments, and metadata in channels and direct messages the bot can access.
  • Links and media URLs included in messages, including URLs used to retrieve GIF, invite, or video previews.

The exact information depends on Discord permissions, enabled gateway intents, available Discord features, and what the operator has configured. The Client does not sign users in with Discord OAuth or ask for their Discord password.

2. How information is used

I use this information to operate the bot-backed interface: show Discord conversations and server structure, provide messaging and interaction features, maintain unread indicators, render previews, and respond to actions an authenticated Client user requests. The app forwards live Discord data to connected, authenticated browser sessions.

Message content is handled in memory to deliver and render conversations. The application’s JSON files do not serve as a message archive; messages remain subject to Discord’s own storage and retention. Runtime errors may appear in the process or hosting logs if the operator or host records them.

3. Local files and retention

Depending on enabled features, the self-hosted server can store the following information in JSON files in its application directory:

  • unread_channels.json: channel IDs marked unread; it does not contain the messages.
  • favorite_gifs.json: GIF URLs selected as favorites.
  • gif_preview_cache.json: GIF/media preview results associated with source URLs.
  • dm_cache.json: IDs used to restore the list of previously opened direct-message conversations.
  • guild_sidebar.json: server ordering, folder membership, and folder display preferences.

These files remain until I delete them or the host removes the application data. They are not automatically sent to GitHub Pages. Do not put private runtime data, Discord credentials, or user data into a public repository. The bot token and web-client password belong in the server’s private environment configuration, never in this static site.

4. Access control and security

The web client is protected by the configured web-client password and a session cookie. I control who receives that password and who can reach the host. Anyone who can use the authenticated client may see data that the bot can access and may have the ability to perform actions granted by the bot’s Discord permissions.

Use a unique, strong password; keep the bot token private; restrict network access; keep dependencies updated; and use HTTPS when exposing the client beyond a trusted local network. No internet-connected system can be guaranteed completely secure.

5. Discord and other services

The Client communicates with Discord’s API and may request resources from Discord’s CDN. Depending on content and features used, the server or browser may also request preview or media resources from external websites and providers linked in messages. Those services receive ordinary connection information and the URL or resource requested, and their own privacy policies apply. I do not control their practices.

The web client currently loads Tailwind CSS and Font Awesome from their public CDNs. A browser opening the client may therefore connect to those CDN operators, which can receive ordinary request and connection information. GitHub Pages hosts this policy website when enabled. GitHub may process technical information such as IP address and request metadata to deliver and protect the pages. See each provider’s current privacy statement for its practices. This policy website itself does not add analytics or advertising trackers.

6. Sharing

I do not sell personal information. Information is shared with Discord as needed for bot operation, with the authenticated browser sessions connected to the instance, and with hosting or infrastructure providers used to run the service. I may disclose information when required by law or reasonably necessary to protect users, the service, or others.

7. Your choices and requests

For questions or requests about information held by this bot instance, contact me through my Discord profile. I can remove the local JSON files listed above. Requests concerning information held by Discord or an external media provider must be directed to that provider. Rights and response requirements depend on your location and applicable law.

8. Children

The Client is not intended for anyone who may not lawfully use Discord under Discord’s minimum-age rules or applicable local law. I do not knowingly use the Client to collect information directly from children in violation of applicable law. Contact me if you believe a child’s information has been handled improperly.

9. Changes and contact

I may update this policy when the Client or its data handling changes. The revised policy will be posted on this page with a new effective date.
